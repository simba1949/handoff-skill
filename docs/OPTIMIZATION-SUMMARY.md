## 核心设计原则确认

基于拷问会议，以下设计原则在优化中得到贯彻：

1. **命令缩减**：9 → 5（砍掉 pitfall/status/clear/archive-list，合并子参数）
2. **模板瘦身**：12 节 → 4 节（砍掉 git 已有信息）
3. **互不越界**：write=会话边界，update=会话中途，严格互斥
4. **read 轻型**：摘要 + 询问，不倾倒全文（覆盖 status 价值）
5. **归档冻结**：一经归档永不修改，快照真相
6. **纯 standalone**：不探测框架、不用指针、不寄生归档
7. **接受重叠**：与三大框架（OpenSpec/SuperPowers/planning-with-files）重叠已知，主动接受
8. **不可替代价值**：只有"踩坑记录"独占，其余能力都重叠

## 总结

本次优化基于 13 轮拷问会议的最终决策，核心是**诚实表达设计取舍而非掩饰妥协**：

- 明确"互不越界"不是建议而是约束
- 坦承与其他框架的重叠和代价
- 详化关键流程（archive load）的安全机制
- 提供实用场景指引而非抽象命令列表

handoff-skill 现在是一个**故意 standalone、接受重叠、以"踩坑记录"为唯一不可替代价值**的交接工具。这是设计选择，非实现缺陷。
