# /handoff:update

会话中途局部更新 HANDOFF.md 指定章节。用户驱动，不重新扫描项目。

## 使用时机

✅ **应该使用的场景**：
- 会话进行中，刚做了一个技术选型决策，想记录到"决策记录"
- 会话进行中，踩了一个坑并解决，想追加到"踩坑记录"
- 会话进行中，任务进度变化（如完成了某个子任务），想更新"当前进度"
- 会话进行中，发现"上下文"描述不准确，想微调

❌ **不应该使用的场景**：
- 会话边界（新会话开始/会话结束时应该用 `/handoff:write`）
- 想全量刷新所有章节（应该等会话结束用 `/handoff:write`）
- 项目状态发生重大变化需要重新扫描（应该用 `/handoff:write`）

## 用法

**方式 1（结构化）**：
```
/handoff:update decisions
决策：选用 React Query 而非 Redux
原因：服务端状态管理更简洁，减少样板代码
```

**方式 2（自然语言）**：
```
/handoff:update
我刚踩了一个坑：Vite 在 WSL2 下热更新失效，需要配置 server.watch.usePolling: true
```

## 可用章节

HANDOFF.md 共 4 个章节，update 可更新的章节：

| 章节 | 英文 | 含义 | 更新方式 |
|---|---|---|---|
| `上下文` | `context` | 一句话任务 / 为什么做 / 技术背景 | 替换该节正文，保留节标题 |
| `当前进度` | `progress` | 已完成 / 进行中 / 卡点 / 下一步 | 替换该节正文，保留节标题 |
| `决策记录` | `decisions` | 为什么选 X 不选 Y（表格，时间倒序） | 在现有表格数据行顶部追加一行 |
| `踩坑记录` | `pitfalls` | 踩过什么坑 + 如何解决（列表，时间倒序） | 在现有条目顶部追加一条 |

英文名用于 `/handoff:update [context\|progress\|decisions\|pitfalls]`；中文名同样接受。

## 执行步骤

1. 读取项目根目录 `HANDOFF.md`。
   - 不存在时提示：`未找到 HANDOFF.md，请先执行 /handoff:write 创建`，然后停止。
2. 识别用户要更新的章节：`上下文`、`当前进度`、`决策记录`、`踩坑记录`。
   - 用户明确指定章节时按指定章节处理。
   - 用户使用自然语言且只有一个明显目标时自动识别。
   - 无法明确识别时先说明需要章节和内容，不写入文件。
3. 按规则更新，保留其他章节原样：

   | 章节 | 更新方式 |
   |---|---|
   | 上下文 | 替换该节正文，保留节标题 |
   | 当前进度 | 替换该节正文，保留节标题 |
   | 决策记录 | 在现有表格数据行顶部追加一行 |
   | 踩坑记录 | 在现有条目顶部追加一条 |

4. 更新 `> 最后更新：YYYY-MM-DD HH:MM`；保留已有 `> 派生自：<文件名>`。
5. 输出修改的章节、替换/追加方式和一行摘要。

## 安全约束

- update 是会话中途的用户事实补丁，不扫描 Git、代码或测试，不替用户推断未提供的原因。
- 决策记录至少需要“决策内容”和“选择原因”；踩坑记录至少需要“问题”和“解决/规避”。缺少关键字段时先向用户索取，或明确标记“未知”，不要编造。
- 默认不删除历史记录。需要更正时追加一条带“更正”标记的记录；只有用户明确要求且确认后才删除。
- 会话边界的全量状态刷新使用 `/handoff:write`，不要用 update 代替。
