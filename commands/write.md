# /handoff:write

在会话边界全量重综合 `HANDOFF.md`。这是 AI 驱动的状态快照，不是用户定点补丁。

## 适用时机

- 新任务/新会话开始，首次创建或重新核对交接文档
- 会话结束前，记录本次会话产生的项目状态
- 长时间停滞后恢复，或项目发生重大结构变化

会话中途只使用 `/handoff:update`；不要用 write 代替定点更新。

## 执行步骤

1. 读取 `HANDOFF-template.md` 和现有 `HANDOFF.md`（如果存在）。
2. 扫描当前项目状态：Git 分支、提交、未提交变更、测试/构建错误、TODO/FIXME，以及当前任务相关文件。
3. 生成或更新项目根目录的 `HANDOFF.md`，严格保留四节：上下文、当前进度、决策记录、踩坑记录。
4. **保留历史记录**：现有“决策记录”和“踩坑记录”默认原样保留，并将能从本次会话可靠确认的新记录追加到顶部；不要因为代码扫描无法推断原因就删除历史记录。
5. **更新状态字段**：根据当前扫描重写“上下文”和“当前进度”；未知信息写“未知”或“无”，不要编造。
6. 如果旧文件有 `> 派生自：<文件名>`，原样保留该直接父归档标记；首次生成则不添加该行。
7. 更新 `> 最后更新：YYYY-MM-DD HH:MM`。
8. 输出本次生成的四节标题、当前卡点和下一步，并提示下次使用 `/handoff:read`。

## 覆盖与保留规则

- write 可以重写上下文和进度，但**不得清空或改写已有决策/踩坑历史**。
- 如果用户明确要求“从零开始/清空历史”，先说明将丢失哪些内容；只有用户明确确认后才清空。
- 不存在 `HANDOFF.md` 时按模板创建空历史记录，不要用项目中的示例数据填充真实记录。
- write 不能可靠推导“为什么选择 X 而不是 Y”；这类理由应由用户在会话中使用 update 记录。

## 与 update 的边界

| 维度 | write | update |
|---|---|---|
| 时机 | 会话边界 | 会话中途 |
| 驱动 | AI 扫描并综合项目状态 | 用户提供明确事实 |
| 范围 | 上下文/进度重综合；历史记录保留 | 指定章节替换或追加 |
| 扫描 | 扫描项目 | 不扫描项目 |

如果用户要求在会话中途全量刷新，说明应等到会话边界使用 write；当前只执行安全的 update。
